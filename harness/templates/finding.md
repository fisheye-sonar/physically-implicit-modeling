# <Concept> — findings

One file per concept. **Current understanding** is mutable and rewritten as understanding
changes; the dated log below it is append-only, newest first.

Entries are written by the agent as evidence arrives — there is no approval queue. Each entry
carries a **status** (how strongly it is held) and its **evidence**. **★** marks significance
and is placed by the human.

---

## Current understanding

_Updated YYYY-MM-DD._

The live synthesis, in a few sentences. What do we believe about this concept right now, and
how strongly? Link to the entries that carry the weight. If this contradicts an entry below,
one of them is wrong — fix it now.

**Open:** the questions this concept has not settled.

## Log

**Evidence:** notebook · scratch note · run codes · dataset/split · n =

The result, stated as quantities. Include the metric names and units. State scope and caveats
in the same breath as the claim, not in a separate section further down.

**Why it matters:** one or two sentences.

**Caveats / what would falsify it:**

*(If claiming `established`, state the case explicitly: replicates across what, survived what
attempt to break it, what depends on it.)*

### YYYY-MM-DD — <correction>

**Status:** `replicated`
**Supersedes:** YYYY-MM-DD *(or **Retracts:** YYYY-MM-DD)*

What was wrong, how it was caught, and what is true instead. **The superseded entry stays
exactly as written** — the trail of how understanding changed is often the most informative
thing in the file.
